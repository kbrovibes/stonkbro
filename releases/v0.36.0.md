# v0.36.0 — HOOD theme style

## Problem

stonkBRO already had a good dark mode, but it was the *only* axis of visual choice. The app's chrome (cards, tabs, chips) still read as a generic mobile web app: uniform borders everywhere, P&L set at the same size as the labels around it, rectangular controls, no motion vocabulary. The brief was to ship a second, sleeker visual identity — Robinhood-grade — **without** risking the look people already use every day.

## Approach: a third theming axis, not a fork

HOOD is a *theme style*, orthogonal to the existing light/dark *mode*. Four combinations must each look deliberate: Classic × light, Classic × dark, HOOD × light, HOOD × dark.

The safety guarantee is structural: HOOD is activated only by `data-theme-style="hood"` on `<html>`, and **every** HOOD rule is scoped under that attribute selector. With the attribute absent, no HOOD rule matches, so Classic renders exactly as it did before. No component was forked and no component branches on the theme at render time.

Components carry inert **marker classes** (`hood-card`, `hood-money-hero`, `hood-pill`, `hood-micro`, …) that are present in both styles and only pick up declarations under the HOOD attribute. This beats a `useThemeStyle()`-driven conditional-class approach on three counts: it works in Server Components (`Header` is an async RSC), it can never produce a hydration mismatch, and it cannot flash on load.

`hood.css` and `hood-motion.css` are deliberately **unlayered**. Tailwind v4 puts its utilities in `@layer utilities`, and unlayered rules beat layered ones regardless of specificity — that is precisely how `.hood-card` restyles an element already carrying `bg-white rounded-xl` without touching the markup's existing classes.

## Design system

### Palette

Both blocks override the same 26 per-mode base tokens, so nothing inherits a Classic value by accident (verified by a parity audit, below).

| Token | HOOD × light | HOOD × dark |
|---|---|---|
| `--background` / `--surface` | `#FFFFFF` | `#000000` |
| `--surface-elevated` | `#FFFFFF` | `#0A0B0D` |
| `--surface-muted` | `#F5F5F3` | `#141518` |
| `--surface-sunken` | `#EFEFED` | `#000000` |
| `--border` | `rgba(28,25,23,.09)` | `rgba(255,255,255,.08)` |
| `--border-subtle` | `rgba(28,25,23,.055)` | `rgba(255,255,255,.05)` |
| `--border-strong` | `rgba(28,25,23,.16)` | `rgba(255,255,255,.14)` |
| `--text` | `#0A0A0B` | `#F7F8F8` |
| `--text-muted` | `#46484D` | `#A8ADB4` |
| `--text-subtle` | `#6B6E75` | `#80858D` |
| `--text-faint` | `#9A9DA3` | `#5E636B` |
| `--gain` | `#04843C` | `#00C805` |
| `--gain-strong` | `#026B30` | `#45E06A` |
| `--loss` | `#D93A46` | `#FF6B6B` |
| `--loss-strong` | `#B0242F` | `#FF9494` |
| `--accent` | `#04843C` | `#00C805` |
| `--accent-hover` | `#026B30` | `#45E06A` |

Three decisions worth defending:

- **`--accent` collapses into the money-green.** Classic keeps a sky-blue CTA colour distinct from gain-green. HOOD deliberately merges them: one voice for "this is good / this is actionable", which is what makes Robinhood read as Robinhood. The cost is that a link and a gain are the same hue; the benefit is a single, unmistakable brand colour.
- **The greens differ by mode on purpose.** `#00C805` is the real Robinhood green and it only sings on black — on paper-white it contrasts at ~1.9:1 and is unreadable as text. HOOD light therefore uses `#04843C`, which keeps the hue family and passes AA at body sizes.
- **Dark gets a text-colour flip on filled CTAs.** Because `--accent` is a vivid green on dark, `bg-accent text-white` buttons would be unreadable. One scoped rule — `:root[data-theme-style="hood"].dark .bg-accent { color: #04120A }` — flips every filled primary action to near-black text. Not needed in light, where the accent is already dark.

`--brand` (the `stonkBRO` wordmark green, `#00C805`) is untouched in both styles — it is identity, not semantics.

### Type scale

| Role | Size | Weight | Tracking | Numerals |
|---|---|---|---|---|
| `.hood-money-hero` | `clamp(34px, 8.5vw, 44px)` / 1.02 | 800 | `-0.032em` | tabular |
| `.hood-money-lg` | 22px / 1.1 | 700 | `-0.022em` | tabular |
| `.hood-money` | inherits | 700 | `-0.012em` | tabular |
| `.hood-micro` | 10px | 600 | `+0.10em`, uppercase | — |
| `.hood-micro-11` | 11px | 600 | `+0.085em`, uppercase | — |

Tabular numerals matter more than the size does: without them, a live-refreshing P&L reflows on every tick.

### Geometry

`--hood-radius-hero: 20px` (hero cards only), `--hood-radius-card: 14px`, `--hood-radius-control: 10px`, pills at `999px`. Cards flatten — hairline `--border-subtle` instead of a full border, `box-shadow: none` on dark (a shadow is invisible on `#000` anyway) and a 1px + soft ambient shadow on light. Selected pills/tabs invert to `background: var(--text); color: var(--surface)`, making the active control the highest-contrast element in its row.

**The hero row wraps.** A 34px number and a three-column stat group cannot share a line on a 390px phone — Classic already sits flush against the right edge at 24px, and HOOD's larger numeral pushed the third column off. Rather than shrink the money, `.hood-hero-row` sets `flex-wrap: wrap` and `.hood-statgroup` takes `margin-left: auto`: the number owns its line and the stats drop beneath it, right-aligned. This is the Robinhood portfolio header, and on a tablet (`max-w-2xl`) there is room, so they stay side by side. `.hood-stat` also dials tracking back to `+0.04em` (versus `.hood-micro`'s `+0.10em`) because those three labels are width-constrained in a way the standalone micro-caps are not.

### Motion

Everything in `hood-motion.css` sits inside a single `@media (prefers-reduced-motion: no-preference)` block — including the pressed-state scale. A reduced-motion user gets the complete HOOD look with zero movement.

| Effect | Duration | Easing |
|---|---|---|
| Card / hero mount (`hood-rise`: fade + 6px translate) | 240ms | `--hood-ease` = `cubic-bezier(.22, 1, .36, 1)` |
| List stagger step (capped at 8 children ≈ 210ms tail) | 30ms | — |
| Tab-panel cross-fade (`hood-panel`) | 170ms | `--hood-ease` |
| Press feedback `scale(0.97)` | 120ms | `ease-out` |
| Background / border / colour transitions | 150ms | `--hood-ease` |
| P&L colour tick | 200ms | `--hood-ease` |
| Skeleton shimmer | 1400ms loop | `linear` |

No JavaScript animation and no count-up hook: a colour transition on a number is free on the compositor, whereas per-frame number interpolation is not, and the portfolio page already re-renders on live-quote fetches. Pull-to-refresh was left entirely alone, as specified.

## Verification

- `npx tsc --noEmit` clean; `npm run build` compiles successfully.
- **Token-parity audit**: of the 26 tokens the base theme defines per-mode, HOOD overrides all 26 in *both* its light and dark blocks — zero tokens overridden in one mode only. Of the 9 HOOD-only tokens, the 5 that are mode-dependent (`--hood-chrome`, `--hood-shadow-card`, `--hood-shadow-hero`, `--hood-shimmer`, `--hood-shimmer-hi`) are declared in both blocks; the 4 geometry/easing tokens are intentionally mode-independent.
- **Motion audit**: the compiled CSS contains exactly one `prefers-reduced-motion` block, and every HOOD `animation`/`transition` declaration is inside it.
- **Classic-safety audit**: `git diff` over `src/components` and `src/app/(app)` adds only `hood-*` class tokens, apart from the new Settings selector.

## Notes

- The choice is per-device (localStorage, key `stonkbro-theme-style`), not synced to the account — same as the font theme.
- The one non-visual behaviour change in Classic: the portfolio results container is now keyed by the active filter, so switching tabs remounts the cards. This resets a `ChainCard`'s expanded/live-quote state on tab change — previously that state leaked across filters because cards were keyed by array index.
- `hood-chrome` uses `backdrop-filter`. Where it is unsupported the element falls back to the semi-transparent `--hood-chrome` colour, which is still legible over the canvas.
- Adding HOOD styling to a new surface means adding a marker class, not a conditional — reach for `useThemeStyle()` only when the difference genuinely needs JavaScript.
