# v0.32.0 — Explosive Finder: Per-Sector State, Research All, 24h Cache

## Problems fixed

1. One global "running" flag froze the page: changing the sector dropdown mid-scan offered no way to start the new selection.
2. No way to research all sectors at once.
3. Results vanished on reload — every visit re-paid the AI call.

## Implementation

- `explosive_scans` table (migration `20260816130000`, applied to prod): cache keyed by selection (sector slug or "all"), 24h TTL read via `getLatestExplosiveScan(selection, 24)`.
- API: new GET = cache-only lookup (never scans, never creates job rows). POST serves the <24h cache unless `?refresh=1`; live path keeps its `runTracked` job wrapper (selection in meta) and writes the cache row on success. Additive response fields `cached`, `scannedAt`. Custom-tickers requests bypass caching.
- `useExplosiveScans` hook: per-selection state map (idle/loading-cache/running/done/error + data/age), double-run guard, sequential `runAll` with progress, unmount-safe.
- Page: dropdown switch always shows that selection's own state; "Re-scan" replaces the start button once a result exists; "Research All Sectors" with per-sector tick list; age line on cached results. Result rendering untouched.

## Notes

- Research All without `refresh` means fresh-cached sectors are effectively free; only stale ones spend AI calls.
- Until-applied fallback existed (cache miss → live scan) but the migration is applied, so caching is active from this deploy.
