# v0.43.2 — Found the actual reason briefing TTS kept failing

## What was really going on
v0.43.0 shipped chunked TTS as a fix for the near-total midday/close audio failures, on the theory that the free endpoint was just unreliable on long calls. That chunking is real and worth keeping — but after backfilling, a subset of "close" sessions kept failing with the identical error even chunked: `Stream closed before the synthesis completed (no turn.end received)`.

Reading `msedge-tts`'s source (`_SSMLTemplate` in `node_modules/msedge-tts/dist/MsEdgeTTS.js`) showed it interpolates the input text directly into an XML/SSML template with **zero escaping**. Pulling the actual transcript for one of the still-failing rows found the smoking gun immediately: *"...the S&P 500 down just under half a percent..."* — a bare `&`, which breaks the XML server-side.

Verified directly against the endpoint with the literal production transcript text: the unescaped version reproduces the exact same error message; the same text with `&`/`<`/`>` escaped synthesizes cleanly. `premarket` transcripts happened to phrase the index as "S and P" and so never hit this; `midday`/`close` routinely wrote "S&P" and failed on essentially every run.

## Fix
`src/lib/briefing/tts.ts`: escape `&`, `<`, `>` before the text ever reaches `msedge-tts`. `CHUNK_RETRIES` also bumped 2 → 3 as extra headroom, though the escaping is what actually closes the gap.

## Backfill
Re-ran `/api/cron/briefing-backfill` after deploying — all remaining failed "close" sessions (which all shared the identical ampersand-triggered error) now have audio.
