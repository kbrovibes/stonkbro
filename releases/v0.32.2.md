# v0.32.2 — Learn Progress Fix

**Bug**: `useDebouncedSave` in LessonClient had one timer/payload slot shared by lesson-start, scroll, and completion saves. Any save scheduled within 3s after `completed: true` replaced it; unmount cleared the timer. DB evidence: cs-sndk had 6 rows with deep scroll positions but only one `completed = true`, quiz_score null everywhere (onQuizComplete never wired), time_spent_seconds all 0.

**Fix** (`src/components/learn/progressSync.ts` + LessonClient rewrite):
- `saveCritical` — immediate keepalive POST for completed/quiz; failures and offline saves land in a localStorage queue (`learn-progress-queue-v1`, capped 50) flushed on `online`/next mount.
- `createSoftSaver` — per-lesson merged+debounced channel for scroll/timeSpent, flushed on pagehide and unmount; offline soft data is dropped (harmless).
- Quiz completion → saves score/answers critically AND marks the lesson complete.
- Next/Complete-Module clicks call markComplete before navigating.
- Server: `saveLessonProgress` only ever sets completed to true (no downgrade).
- One-time backfill: cs-sndk rows flipped to completed (user attested full completion).

Applies to all Learn modules — LessonClient is shared by curriculum lessons and case studies.
