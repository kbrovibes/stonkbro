# v0.30.0 — Jobs Center

## Problem

Async operations (chain refresh, Hindsight backfill, research, scans, crons) showed progress only on the page that started them. Navigate away and there was no way to know what was still in flight.

## Architecture

- **`app_jobs` table** (migration `20260816040000_app_jobs.sql`, applied to prod): kind, label, trigger (`manual`/`cron`/`auto`), status (`running`/`completed`/`failed`/`cancelled`), progress text, error, meta jsonb, `cancel_requested`, created_by, started/finished/duration. RLS: authenticated read; writes via service role only.
- **`src/lib/jobs/tracker.ts`**: `runTracked(opts, fn, onCancelled?)` opens a row, hands `fn` a ctx (`checkCancelled()` throws `JobCancelledError` when a cancel was requested; `progress(text)` updates the row), closes as completed/failed/cancelled. Every tracker call is best-effort — tracking can never break the wrapped operation. `sweepStaleJobs()` marks rows running >15 min as failed (dead function) and runs on every jobs-API read. Running count is an exact head-count query, independent of list limit.
- **`src/lib/jobs/registry.ts`**: kind → label + cancellable. Kinds: chain-scan, time-machine-backfill, research, explosive-scan, bloodbath-scan, csp-hunter-scan, pmcc-scan, portfolio-manager-scan, market-monitor, daily-briefing, recommendations.
- **`/api/jobs`**: GET (sweep + list + running count; 401 for guests), POST `{action:"cancel", id}`.

## Instrumented routes

manual: portfolio option-chains live refresh, time-machine backfill, research POST, explosive POST, bloodbath live scan, csp-hunter POST, pmcc-scan, portfolio-manager scan (`after()`), recommendations background refresh. cron: portfolio-chains, bloodbath, market-monitor, daily briefing (+ portfolio-manager ride-along). Cache-hit paths create no rows. `/api/flow` was deliberately left untracked — it's auto-fetched by the Plays page and would create a row per visit.

## Cancellation

Cooperative only (serverless can't kill a lambda): cancel sets `cancel_requested`; jobs check between units of work.
- Chain scan: `getOptionChains(startDate, hooks?)` checks between accounts and at activity-window recursion depth ≤2; hooks optional, zero change for existing callers.
- Hindsight backfill: checks per month, progress "2026-03 (3/12)", returns partial success (`cancelled: true` + completed months).
- Cancelling a non-cancellable kind just flags the row (documented in UI as button absence).

## UI

- `JobsIndicator` in the header (before ProfileMenu): pulse icon, count badge when running > 0, 20s poll skipped while tab hidden, focus/visibility refetch, hidden on 401.
- `/jobs`: day-grouped list, status dots (running = pulsing + live elapsed timer via one shared 1s interval), CRON/MANUAL/AUTO chips, relative times + durations, 2-line-clamped expandable errors, All/Running/Completed/Failed pills, Cancel → "Cancelling…" (optimistic, reconciled by next poll). 10s auto-refresh while anything runs, else 60s.

## Notes / edge cases

- Early-return routes (portfolio-manager `after()`, recommendations fire-and-forget) have job rows that outlive the HTTP response — the stale sweep is their backstop.
- Cancelling the manual chain scan surfaces as the route's normal error response (portfolio page shows "refresh failed"); the job row correctly shows cancelled.
- Backfill's "no transaction history" 502 records a completed job (the scan itself succeeded; there was just nothing to write).
