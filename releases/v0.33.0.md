# v0.33.0 — Face ID App Lock

Device-local WebAuthn gate (`src/lib/biometric.ts`, `src/components/BiometricLock.tsx`, Settings `BiometricSection.tsx`).

- Enroll: `navigator.credentials.create` (platform attachment, userVerification required, residentKey discouraged, attestation none) from the toggle tap (Safari needs a user gesture for create()). Credential rawId stored base64url in localStorage `biometric-lock-v1`.
- Unlock: `credentials.get` with allowCredentials=[stored id]; auto-fired on mount and on re-lock; NotAllowedError = cancel (button retry), InvalidStateError/NotFound = credential gone → fail-open "Disable lock and continue" (documented: the alternative bricks the app; Supabase session + privacy PIN remain).
- Re-lock: visibilitychange timestamps; >60s hidden → lock + re-prompt. Reload re-locks (in-memory state).
- Flash prevention: inline script in (app) layout adds `bio-locked` class to <html> pre-paint when the flag exists; CSS hides `#bio-shell` (a display:contents wrapper so body flex layout is untouched); BiometricLock removes the class after a successful assertion. Children always render in the tree → hydration-safe.
- Threat model: privacy gate for someone holding the phone (same class as the PIN mask), NOT an auth boundary — assertion is not server-verified; zero deps, no migrations, works offline.
- Needs on-device verification: iOS standalone-PWA auto-`get()` on mount (fallback button covers rejection).
