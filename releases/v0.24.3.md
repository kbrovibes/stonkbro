# v0.24.3 — Portfolio option-chain rebuild

## Problem

The portfolio page's "Open chains" logic (`getOptionChains` in `src/lib/snaptrade/client.ts`) chained SELL-first contracts linearly: walk contracts by start date and append whenever the current contract started within 3 days of the *previous appended contract's* close. Two failure modes:

1. **Overlap merging.** `daysDiff <= 3` is also true for negative gaps, so simultaneous parallel positions (e.g. three concurrent MU short-put lines being rolled independently) braided into one 22-leg mega-chain whose `open_units` came from whichever contract happened to sort last.
2. **Orphaned rolls.** Once the linear sequence's last contract was OPEN, a genuine same-day roll elsewhere in the group couldn't attach. Real case: 7/28 BUY-to-close MU 850 PUT 8/21 @ $104.95 (inside the mega-chain) + SELL MU 800 PUT 9/18 @ $103.41 (orphaned as a fresh 1-leg chain). The orphan showed net +$20,680 and "close ≤ $103.40 → chain profit" — closing there would actually be a large loss because the paired buy-back lived in the other chain.

## Fix

**Roll pairing (per underlying+type group):**
- Candidate roll targets = every SELL leg (initial open *or* add-on to an existing contract).
- Each BUY-to-close pairs with the best unconsumed target within 0–3 days after it, scored by day gap (dominant), then contract-count match, then strike proximity.
- Each close has ≤1 successor and each SELL event is consumed ≤once ⇒ lineages are disjoint in-trees, each with exactly one terminal (open / expired / assigned / unrolled-close) contract. `status`, `end_date`, `open_units` come from that root, so breakeven `net_pnl / |open_units| / 100` is now meaningful.
- Expiration/assignment is terminal: a new sell after expiry starts a fresh chain (previously it silently continued the settled chain).

**Chain trimming (`MAX_CHAIN_DAYS = 42`):** a chain spanning >6 weeks has its oldest contracts popped off and emitted as standalone settled chains (own status/end date/close month) until the remainder fits — so long-running roll campaigns stop hiding realized P&L from monthly totals. The live root contract is never trimmed.

**UI (`src/app/(app)/portfolio/page.tsx`):**
- Breakeven line is direction-aware: shorts "Close ≤ $X → chain profit" / "In the hole $Y"; longs "Close ≥ $X → chain profit" / "Any close locks in profit".
- "If closed now" live-quote math: `net_pnl + open_units × mid × 100` (shorts pay to close, longs receive).
- Collateral badge/summary only for *short* puts; Monthly best-case list excludes long chains.

## Verification

MU now shows three parallel open lineages — the Sep-18 800P chain carries its 850→850→800 roll history with breakeven $75.72, the 700P chain $29.29, and the 750P line correctly reads "in the hole" — plus settled June contracts feeding June's monthly total.
