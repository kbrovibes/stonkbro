# v0.42.0 — Portfolio opens up, ticker chart tabs, option-chain fixes

## Summary
Portfolio moves from a hardcoded owner-only allowlist to a real request/approve flow, with each approved user getting their own isolated, encrypted SnapTrade identity. Alongside that: the ticker page's confusing fixed sparkline gets a real time-windowed price chart, and three option-chain reconstruction bugs are fixed — roll leg ordering, a fully-rolled position fragmenting on an arbitrary time window, and partial rolls showing up as unrelated positions.

## Portfolio access, opened up

**The problem**: Portfolio (`/portfolio`) was gated by a two-email hardcoded allowlist in `src/lib/portfolio-access.ts`, and every SnapTrade call in `src/lib/snaptrade/client.ts` used one hardcoded module-level identity (`SNAPTRADE_USER_ID`/`SNAPTRADE_USER_SECRET`). There was no path for anyone else to use the feature short of editing the allowlist and redeploying, and no way for them to bring their own brokerage data even if they could.

**The flow now**:
1. Any signed-in user sees the Portfolio nav entry (previously hidden entirely for non-owners) and, if not approved, a "Request access" prompt on the page itself.
2. Requesting inserts a row in the new `portfolio_access_requests` table and a `kind: "access_request"` alert.
3. The owner sees it in the alert banner — `AlertBanner.tsx` renders **Approve**/**Deny** buttons for this alert kind instead of Open/Dismiss, the first alert type with real actions — or in a new admin-only "Portfolio access requests" section in Settings (`AdminAccessSection.tsx`), which self-hides for anyone the admin API 403s.
4. Approving calls `POST /api/admin/portfolio-access`, which registers the requester as a brand-new SnapTrade end-user (`authApi.registerSnapTradeUser`) and stores their `userSecret` AES-256-GCM-encrypted in a new `user_snaptrade_credentials` table.
5. The approved user now sees a "Connect your brokerage" prompt on Portfolio instead of the request prompt. It sends them through SnapTrade's own hosted connect portal under their own identity — this app never sees their actual brokerage login.
6. Once linked, their Portfolio page just works — reading live from SnapTrade under their own identity.

**Security**: `user_snaptrade_credentials` has no client-readable RLS policy at all — not even for the owning user, only `service_role`. `src/lib/snaptrade/secrets.ts` does the encryption (Node `crypto`, AES-256-GCM); decryption happens only server-side, only at the exact moment of a SnapTrade call, and the plaintext is never returned in an API response or logged. Requires a new env var, `SNAPTRADE_SECRET_ENCRYPTION_KEY` (32-byte hex).

**Backward compatibility**: every exported function in `src/lib/snaptrade/client.ts` gained an optional trailing `creds?: SnapTradeCreds` parameter that defaults to the existing owner identity when omitted. The owner's own code paths — including the cron-cached `portfolio_chain_scans` table — are unchanged. Other approved users always fetch live; no cron/cache changes were made for them.

**Scope**: only `/portfolio` itself is request-based. Time Machine, Taxes, Daily Briefing, and ticker research stay on the original hardcoded allowlist (`hasPortfolioAccess`) — they weren't built with multiple real users in mind and are out of scope for this pass. The More menu's Portfolio group was split: the "Portfolio" link is now always visible to signed-in users, while Daily Briefing / Portfolio Manager / Hindsight moved into a still-gated "Portfolio Insights" group.

## Ticker page: a real price chart

The default (refresh) theme's ticker screen showed a fixed-window sparkline plus IV/IVR/RSI/VOL badges — no timeframes, no hover, no percent change per point. Confusing enough to read as "some IV chart nobody knows how to use." Added `src/components/refresh/PriceChart.tsx`: a proper 1D/1W/1M/3M/1Y/YTD chart with hover-for-date-and-%, matching what the classic theme's `StockChart.tsx` already had. A `Price`/`Stats` segmented switch on the chart card defaults to Price; the old badge card is still there under Stats.

## Option chains: three reconstruction bugs

All three live in `getOptionChains` (`src/lib/snaptrade/client.ts`), which fully recomputes every chain from the raw transaction log on every scan — no incremental state — so all three fixes apply retroactively to every chain, open and historical, on the next cron run or manual refresh. No backfill needed.

- **Roll leg ordering**: merging a rolled lineage's legs re-sorted them by date with SELL ranked before BUY on a tie. Right for disambiguating a single contract's own same-day open+close; wrong for a cross-contract roll merge, where it reordered a same-day "BUY-to-close old, SELL-to-open new" into SELL, SELL, BUY. The merge order (contracts oldest-to-newest, each contract's own legs already chronological) needed no re-sort at all — removed.
- **Fully-rolled positions no longer fragment on elapsed time**: a "settle stale history" rule split a lineage's oldest contracts off once total span exceeded 42 days, so it could attribute realized premium to the month it actually closed in. It was firing on still-open lineages too, which have no `close_month` to attribute anything to — a call rolled continuously since before that window showed as a fake "closed" chain plus a fake "new" open one. Now gated to `root.status !== "OPEN"`.
- **Partial rolls now link instead of looking unrelated**: rolling some but not all contracts of a short position (buy back 2 of 5, resell those 2 at a new strike, leave 3 open) previously showed the new strike as a fully disconnected position — the pairing logic only recognized a roll when a contract's own quantity went fully to zero. Added a second matching pass over partial-reduction legs (using whatever sell events the full-roll pass left unconsumed), producing `splitFrom`/`splitInto` links between the two chains plus a shared `groupId`. Every chain in a group now carries `groupStatus` (`OPEN` if any member is) and `groupNetPnl` (summed across the group) — "is the overall trade still open, was it profitable" is answered directly off either chain. The Portfolio UI marks both halves with a `SPLIT` badge and the caption shows the group's overall status/P&L.

## Other fixes

- **Portfolio page can no longer render silently blank**: a failed initial chain load with no offline signal returned `null`. Now an explicit "Couldn't load your portfolio / Try again" card.
- **Paper desk home page**: the hero now shows overall gain/loss percentage alongside the dollar figure, plus Portfolio value and Cash stat tiles summed across all ten bots (previously portfolio value only).
