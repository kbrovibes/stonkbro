# v0.25.0 — Performance overhaul

Reduce First Load JS and eliminate on-mount data-fetch waterfalls across the daily-driver pages. No behavior, calculation, or visual changes — only bundle composition, code-splitting, loading states, and request parallelism.

Measurement method: First Load JS per route is read from `.next/diagnostics/route-bundle-stats.json` (uncompressed bytes) plus gzip of each first-load chunk. Baseline captured before any change.

## Shared app-shell bundle: -222 KB raw / -59 KB gzip on every authenticated route

`ProfileMenu` renders in the app-shell `Header` on all 40 `(app)` routes. It imported the `@supabase/ssr` browser client solely to call `supabase.auth.signOut()`, dragging the entire Supabase client SDK (~222 KB uncompressed) into the shared chunk loaded by every page.

Sign-out is now a server action (`src/lib/auth-actions.ts`) invoked via a plain `<form action={...}>`. The server clears the auth cookies (the same cookies middleware manages) and redirects to `/`. `ProfileMenu` and the unused `LogoutButton` no longer import `supabase-browser`; only `/login` legitimately does.

|---|---|---|---|---|
| /today | 781 KB | 558 KB | 219 KB | 160 KB |
| /portfolio | 802 KB | 580 KB | 224 KB | 165 KB |

## Learn lesson page: -219 KB raw / -72 KB gzip

`/learn/[moduleId]/[lessonId]` was `"use client"` and imported the entire `CURRICULUM` (~3,300 lines of lesson data across all modules) purely to `find()` one lesson by id — so every module's every lesson was bundled into the route's client JS.

The page is now a server component: it resolves the lesson from `CURRICULUM` on the server and passes just that lesson's `sections` (plus module/lesson metadata and prev/next ids) to a new `LessonClient` island that owns the interactivity (scroll-position save, completion IntersectionObserver, nav). `CURRICULUM` no longer reaches the browser bundle; only the current lesson's content travels in the RSC payload, which was already needed to render.

| Route | Before (raw) | After (raw) | Before (gzip) | After (gzip) |
|---|---|---|---|---|
| /learn/[moduleId]/[lessonId] | 774 KB | 555 KB | 231 KB | 159 KB |

## Auth: one JWT-validation round-trip per navigation instead of three+

`supabase.auth.getUser()` is a network call to Supabase Auth (`/auth/v1/user`) that validates the session JWT — it is not a local cookie decode. Each authenticated navigation invoked it independently in the `(app)` layout, in `Header`, and in the page component, and these run in sequence as the server-render tree resolves.

`src/lib/auth.ts` exports a `getUser()` wrapped in React `cache()`, which memoizes per request. The layout, `Header`, and 14 page components (`home`, `learn`, `learn/[moduleId]`, `covered-calls`, `income`, `admin`, `watchlists`, `watchlists/[id]`, `wheel`, `more`, `dashboard`, `positions`, `positions/[id]`, `risk`) now call it, collapsing 3+ auth round-trips into one and dropping the redundant cookie-store reads that came with each duplicate `createClient()`. Pure server-side latency win; no visual or behavioral change.
