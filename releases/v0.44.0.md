# v0.44.0 — Customizable bottom nav, and three small fixes

## Summary
The bottom nav's 4 middle tabs are now user-configurable from Settings, picked from the app's full page list. Alongside that: a backwards prev/next in the Daily Briefing player, smaller tiles on the More page, and confirmation that last release's option-chain roll-ordering fix is actually live (a screenshot showed stale cached data, not a real bug).

## Customizable bottom nav
Home and More stay fixed. The 4 slots between them are now picked in Settings → Bottom nav, from the full set of app destinations.

- **Data model**: one new column, `user_settings.bottom_nav_tabs text[]`. `null` (every existing row) means "use the current default" — nobody's nav changes until they actively customize it.
- **Destination registry** (`src/lib/nav-destinations.ts`, new): built from `MORE_GROUPS` (`src/components/more-nav-data.tsx`) plus the two destinations that only ever existed as hardcoded bottom-nav tabs and never appeared in the More menu — Options (`/plays`) and Learn (`/learn`). `availableNavDestinations(hasPortfolio)` filters out the portfolio-gated ones for users without access.
- **API**: no new routes. `GET /api/settings` now also returns `navOptions` (the filtered destination list); `POST /api/settings` already generically upserts whatever's in the request body, so `bottom_nav_tabs` needed only a small validation block (≤4 unique, known hrefs) alongside the existing `privacy_pin` validation in the same handler.
- **UI**: `src/app/(app)/settings/BottomNavSection.tsx` (new) — 4 slots, each expanding into an inline picker list on tap; picking immediately saves. "Reset to default" restores the original 4.
- **Rendering**: `src/components/BottomNav.tsx` takes a new `customTabs?: string[] | null` prop (read server-side in `src/app/(app)/layout.tsx` via the existing `getSettings`). The 4 known defaults (Options/Paper/Portfolio/Learn) keep their exact original hand-drawn SVG icons when picked — so the default configuration renders pixel-identical to before this release — and any other destination renders its emoji instead.

## Daily Briefing: prev/next were backwards
`goToOffset` walked `flatQueue`, a chronological (oldest-first) queue built for the *separate* auto-advance-on-end logic. The playlist itself renders newest-first, so pressing "Next" moved to a newer episode — visually the opposite direction of moving down the list. Added a second, display-ordered queue (`displayQueue`, same order as the rendered playlist) that the manual prev/next buttons and their enabled/disabled state now use instead; `flatQueue` still drives auto-advance exclusively, since "continue playing forward" correctly means oldest-to-newest there.

## More page: smaller tiles
`src/components/MoreNav.tsx`'s `MoreTile` and the `/more` page grid (`src/app/(app)/more/page.tsx`) — smaller emoji/text, tighter padding, 5 columns instead of 4.

## Option chains: confirming the fix, not finding a new bug
A screenshot showed an NBIS PUT chain still rendering SELL, SELL, BUY. The `portfolio_chain_scans` cache backing it was from `2026-09-16 20:32 UTC` — before the roll-ordering fix (`v0.42.0`) deployed at `06:34 UTC` the next day. Triggered `/api/cron/portfolio-chains` directly; the fresh scan shows the correct SELL, BUY, SELL, BUY, SELL order for that exact chain.
