# v0.28.0 — Multi-Brokerage Connections (Chase-ready)

## Why

The app was implicitly single-brokerage: the only SnapTrade connection (Fidelity) was created with ad-hoc scripts in May 2026, and there was no in-app way to add another broker. The user now also trades at Chase, and its open contracts + 2026 activity history need to feed the portfolio math.

## What shipped

### SnapTrade client (`src/lib/snaptrade/client.ts`)
- `listConnections()` — wraps `ConnectionsApi.listBrokerageAuthorizations`; returns id, brokerage name/slug, read/trade type, disabled flag, created date.
- `getConnectPortalUrl({ broker?, reconnect? })` — wraps `AuthenticationApi.loginSnapTradeUser` (portal v4, read-only connection type); returns the Connection Portal URL (expires in 5 minutes).
- No changes needed to positions/options/balances/activities: every function already iterates `getAccounts()`, which returns **all** accounts under the single SnapTrade user. A new connection's accounts appear everywhere automatically.

### API (`src/app/api/portfolio/connections/route.ts`)
- `GET` → `{ connections, accounts }`
- `POST { broker?, reconnect? }` → `{ url }` (portal link)
- Auth: Supabase session + `hasPortfolioAccess`, same as `/api/portfolio`.

### Settings UI
- New **Brokerages** group (`settings/BrokerageSection.tsx`): connection list with per-institution account numbers (last 4), Active/Disabled status, "Disabled — Fix" reconnect, "Connect a Brokerage…" (opens portal in new tab; list refreshes on window focus), and **Rebuild 2026 Data**.
- Rebuild = `GET /api/portfolio?include=option-chains&startDate=2025-01-01&refresh=1` (must match `CHAIN_CACHE_START_DATE` so the cached scan the portfolio page reads gets overwritten) followed by `POST /api/portfolio/time-machine/backfill` (idempotent monthly snapshots).
- Shared iOS-style list primitives extracted from `settings/page.tsx` into `settings/ui.tsx`.

## Verified

- `npm run build` green.
- Live smoke test against production SnapTrade credentials: existing Fidelity connection listed; **Chase is a supported SnapTrade brokerage** (slug `CHASE`, enabled, data-only — `allows_trading: false`, which matches our read-only usage); portal link generation returns a valid URL.

## Operator notes

- Linking Chase requires the user to authenticate at Chase inside the SnapTrade portal (credentials + MFA) — cannot be automated.
- How much 2026 transaction history Chase returns is up to the Chase↔SnapTrade integration; verify chains/income after the first sync and rebuild.
- SnapTrade bills per connection on paid plans; a second connection may affect the plan's included quota.
